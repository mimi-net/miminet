## Архитектура тестов

Тесты разложены на четыре слоя. Такое разделение означает, что сами тесты почти
не обращаются к Selenium напрямую: `By` импортируют лишь 6 файлов из 21.

### `conftest.py` — драйвер и фикстуры

Класс `MiminetTester(WebDriver)` расширяет стандартный драйвер хелперами,
которые устраняют две частые проблемы: `StaleElementReferenceException` при
перерисовке страницы и отсутствие явных ожиданий.

| Метод | Назначение |
|---|---|
| `wait_and_click` | Ждёт кликабельности, заново ищет элемент при stale; `scope` привязывает поиск к контейнеру (например, к нужному модальному окну) |
| `drag_and_drop` | Перетаскивание с пересбором локаторов на каждой попытке |
| `wait_until_appear` / `wait_until_disappear` | Ожидание появления и исчезновения элемента |
| `wait_until_text` / `wait_until_value` | Ожидание текста в элементе и значения в поле ввода |
| `wait_for` | Ожидание произвольного условия |
| `run_in_modal_context` | Контекстный менеджер: открытие модального окна и гарантированное ожидание его закрытия |
| `select_by_value` | Выбор опции в `<select>` |
| `exist_element` | Проверка наличия элемента без исключения |
| `get_logs` / `get_console_messages` | Логи браузера через wire-команду `GET_LOG` |

Фикстуры (все уровня сессии):

- `chrome_driver` — headless Chrome через Selenium Grid (`SELENIUM_HUB_URL`);
- `requester` — сессия `requests`, авторизуется POST-запросом на
  `/auth/login.html` под учётной записью `selenium`/`password`;
- `selenium` — берёт куки из `requester` и переносит их в браузер, чтобы не
  проходить логин через UI.

Отдельно определены фикстуры для юнит-тестов: `mock_env_dev`, `mock_env_prod`,
`mock_psycopg2`, `mock_sqlalchemy_inspect`, `mock_db`.

Адрес приложения берётся из `TEST_TARGET_HOST` (по умолчанию `172.18.0.2` —
nginx внутри docker-сети) и `TEST_TARGET_PORT`.

### `utils/locators.py` — локаторы

Класс `Locator` хранит CSS-селектор, xpath и текст по отдельности, а обращение к
незаданной стратегии падает с внятным assert'ом. Привязки к Selenium здесь нет:
`By.*` в файле не встречается, поэтому слой переиспользуется любым драйвером.
Подкласс `DeviceLocator` добавляет `device_class` для узлов сети.

### `utils/networks.py` — доменный слой

Самый крупный хелпер (~630 строк, 82 обращения к Selenium API). Прячет за собой
работу с топологией на canvas (Cytoscape).

`MiminetTestNetwork`:

| Метод | Назначение |
|---|---|
| `add_node` | Добавляет устройство перетаскиванием с панели на холст |
| `add_edge` | Соединяет два узла |
| `open_node_config` / `open_edge_config` | Открывает конфигурацию узла или связи |
| `nodes` / `edges` / `jobs` | Читает JS-состояние страницы |
| `get_nodes_by_class` | Фильтрует узлы по типу устройства |
| `run_emulation` | Запускает эмуляцию и возвращает пакеты |
| `delete` | Удаляет сеть |

`NodeConfig` — конфигурация устройства: `fill_link`, `fill_links`,
`fill_default_gw`, `change_name`, `add_jobs`, `enable_stp`, `disable_stp`,
`configure_vlan`, `submit`.

`NodeType` перечисляет типы устройств: `Host`, `Switch`, `Router`, `Hub`,
`Server`.

Существенная деталь: состояние топологии читается прямо из JS-переменных
страницы через `execute_script` (`return nodes`, `return edges`, `return jobs`,
`return packets`), а часть действий выполняется вызовом функций приложения
(`ShowEdgeConfig()`, `DrawGraph()`, `PostNodesEdges()`, `ShowHostConfig()`).
Это обходит клики по canvas, где обычная автоматизация ненадёжна.

### `utils/checkers.py` — сравнение результатов

`TestNetworkComparator` сверяет построенную сеть с эталоном:

- `compare_nodes` — классы устройств, интерфейсы (`ip`, `netmask`), поле `data`;
- `compare_edges` — `source` и `target` каждой связи;
- `compare_jobs` — `print_cmd` (с нормализацией номеров интерфейсов), `job_id`,
  `host_id`.

При несовпадении бросает `ValueError` с указанием индекса и поля.

## Запуск

### Локально

```sh
./start_all_containers.sh          # приложение
cd front/tests/docker && docker compose up -d   # Selenium Grid
cd front && python -m pytest tests/
```

Grid поднимает `selenium/hub:4.37.0` и `selenium/node-chrome:141.0` в сети
`miminet_network`, хаб доступен на порту 4444.

Переменные окружения: `TEST_TARGET_HOST`, `TEST_TARGET_PORT`,
`SELENIUM_HUB_URL`.

### CI

`.github/workflows/full_test.yml` запускается при push, pull request и по
расписанию в 02:00. Тесты разбиты на 3 шарда по остатку от деления номера файла;
шардируются только файлы верхнего уровня `front/tests/test_*.py`, вложенные
каталоги не собираются.

Перед запуском CI правит `front/.env`: ставит `MODE=dev`, удаляет `BASE_DOMAIN`
и переопределяет `ALLOWED_HOSTS` на `http://localhost`, `http://172.18.0.2`,
`http://172.18.0.3`.

Прочие workflow: `auth_test.yml`, `back_test.yml`, `front_coverage.yml`
(порог покрытия), `linter.yml`, `dependency_review.yml`.

Настройки pytest (`front/tests/pytest.ini`): `-vv -s`, таймаут теста 300 секунд.

## Пробелы в покрытии

**Эмуляция не проверяется в CI.** Метод `run_emulation` в
`utils/networks.py:233` помечен комментарием «This function doesn't work in CI
for unknown reasons». Тесты сетевых протоколов сверяют конфигурацию топологии, а
не результат прогона эмуляции, поэтому расхождение между настройкой и реальным
поведением сети CI не поймает.

**Авторизация в обход UI.** Фикстура `selenium` переносит куки из
`requests`-сессии, то есть форма входа как таковая не тестируется. Сценарии
внешних провайдеров (VK, Google, Yandex, Telegram) вынесены в
`front/src/auth_tests/` и в основной набор не входят.

**Негативные сценарии почти отсутствуют.** Тесты проверяют штатные пути;
поведение при недоступном бэкенде, обрыве соединения или ошибке сохранения не
покрыто. Исключение — валидация ввода в `test_fields_filter.py` и
`test_user_options_input.py`.

**Нет проверок доступа.** Тесты идут от одного пользователя; разграничение прав
(чужая сеть, роль администратора, эндпоинт генерации задач `POST
/ai/generate-task` с ролью >= 1) не проверяется.

**Случайность в построении топологии.** `test_device_connecting.py` выбирает
пары узлов через `random.randint` без фиксированного seed, поэтому падение не
всегда воспроизводится.

**Вложенные каталоги не собираются.** Разбиение на шарды в CI использует `find
-maxdepth 1`, так что тест, добавленный в подкаталог `front/tests/`, молча не
попадёт в прогон.

## Миграция на Playwright

В `front/tests/playwright/` лежит параллельный набор на Playwright. Перенесены
все 18 E2E-файлов и инфраструктура. Selenium-набор не тронут, оба работают
одновременно.

### Что изменилось в коде

**Хелперы ожидания больше не нужны.** Playwright повторяет действие, пока
элемент не станет доступным, поэтому `wait_and_click`, `wait_until_appear`,
`wait_until_value`, `wait_until_text` и циклы пересбора локаторов после
`StaleElementReferenceException` не имеют аналога — их заменяют обычные
`page.click` и `page.fill`. Из 456 строк `conftest.py` осталось около 120.

**Доступ к состоянию страницы переносится один в один.** Чтение JS-переменных и
вызовы функций приложения — основа работы с топологией — переходят из
`execute_script` в `page.evaluate` без изменения логики.

**Локаторы и компаратор переиспользуются, а не копируются.** `Locator` не знал о
Selenium изначально, а `TestNetworkComparator` сравнивает обычные словари,
поэтому `playwright/utils/locators.py` и `playwright/utils/checkers.py`
подгружают исходные модули. Селектор, изменившийся вместе с UI, правится один
раз для обоих наборов.

**Перетаскивание устройств пришлось делать вручную.** `drag_to` не подходит:
Cytoscape отслеживает движение указателя, и прыжок сразу в конечную точку роняет
узел не туда. Работает последовательность `mouse.move` → `mouse.down` →
`mouse.move(steps=10)` → `mouse.up`.

**Инфраструктура проще.** Selenium требует Grid из двух контейнеров (`hub` +
`node-chrome`) в общей docker-сети. Playwright ставит браузер локально командой
`playwright install chromium`, контейнеры не нужны.

**Посимвольный ввод там, где проверяется фильтр.** Фильтры полей навешаны на
события клавиатуры, поэтому значение, выставленное одним присваиванием
(`fill`), их не задело бы. Для таких полей используется
`press_sequentially` — аналог `send_keys`. Обычные поля заполняются `fill`.

**Ожидание промиса не требует отдельного вызова.** Selenium различает
`execute_script` и `execute_async_script` с колбэком; `page.evaluate` сам
дожидается промиса, который вернула переданная функция.

**Клики внутри модального окна выражаются вложенными локаторами.** Одинаковые
id встречаются в нескольких диалогах сразу, и Selenium-версия борется с этим
параметром `scope`. В Playwright диалог находится один раз, а элементы ищутся
внутри него.

### Найденные дефекты

Миграция вскрыла две проблемы, существующие и в Selenium-наборе.

**Устаревший позиционный локатор.** `MyNetworks.get_network_button_xpath`
возвращает абсолютный путь `/html/body/section/div/div/div[id + 2]`. Домашняя
страница выводит перед списком сетей служебные карточки, и после появления
карточки «Задача от ИИ» индекс сместился: `div[2]` теперь открывает модальное
окно генерации, а не первую сеть. В Playwright-версии карточка ищется по
ссылке, которую она содержит (`a[href*="<guid>"]`), — такой локатор переживает
изменения в начале списка.

**`/quiz/test/all` отвечает 500.** Под авторизованной сессией эндпоинт отдаёт
500, без авторизации — 302. Воспроизводится обычным `requests`, без браузера;
оригинальный Selenium-тест падает так же (`1 failed, 5 passed`). Дефект
приложения или локального окружения, к выбору драйвера отношения не имеет.

### Отличие, которое потребовало настройки

Навигация ожидает `domcontentloaded`, а не событие `load`, принятое в Playwright
по умолчанию. Домашняя страница перечисляет все сети аккаунта, и при большом
списке `load` не наступает около 30 секунд, тогда как DOM готов за 0.1 секунды —
замер на 178 карточках:

| Стратегия ожидания | Время `goto` |
|---|---|
| `load` (по умолчанию) | 30.1 с |
| `domcontentloaded` | 0.1 с |
| `commit` | 0.03 с |

Selenium с этим не сталкивался: `driver.get` возвращает управление по готовности
документа. Без настройки тест `test_auth` падал примерно в одном прогоне из
трёх.

### Результат

Оба набора прогнаны на одной машине, против одного и того же приложения, без
юнит-тестов (они драйвера не касаются).

| Набор | Тестов | Прошли | Время |
|---|---|---|---|
| Selenium | 93 | 93 | **4 мин 25 с** |
| Playwright | 89 | 89 | **2 мин 05 с** |

#### Место на диске

| Набор | Что хранится | Размер |
|---|---|---|
| Selenium | `selenium/node-chrome:141.0` | 2.06 ГБ |
| | `selenium/hub:4.37.0` | 647 МБ |
| | **итого** | **2.7 ГБ** |
| Playwright | Chromium + headless shell + ffmpeg | **658 МБ** |

Playwright занимает вчетверо меньше. К этому добавляется, что Selenium держит
два контейнера запущенными всё время прогона, причём ноде задан `shm_size: 2gb`,
тогда как Playwright поднимает браузер на время теста и не требует Docker вовсе.

### Как запускать

Приложение должно быть поднято (`./start_all_containers.sh`). Docker для самих
тестов не нужен: Playwright запускает браузер как обычный процесс.

Установка, один раз:

```sh
uv sync                              # поставит pytest-playwright
uv run playwright install chromium   # ~658 МБ на диске
```

Запуск через скрипт, из корня репозитория:

```sh
sh front/tests/playwright/run.sh                 # весь набор в 4 процесса
sh front/tests/playwright/run.sh test_vlan.py    # один файл
sh front/tests/playwright/run.sh . --headed      # с видимым браузером
```

Скрипт подставляет адрес и число воркеров, остальные аргументы передаёт в
pytest. Переопределяются переменными `TEST_TARGET_HOST` и `WORKERS`. То же
самое вручную:

```sh
cd front/tests/playwright
TEST_TARGET_HOST=127.0.0.1 uv run pytest . -n 4
```

`-n 4` запускает тесты в четыре параллельных процесса: весь набор проходит
примерно за минуту вместо трёх. Больше четырёх воркеров брать не стоит — на
шести прогон стабилен, но на восьми тесты начинают падать из-за конкуренции за
одну учётную запись, а выигрыша уже нет.

`TEST_TARGET_HOST=127.0.0.1` нужен при запуске с хоста: адрес по умолчанию
(`172.18.0.2`) — это nginx внутри docker-сети, снаружи он отдаёт 502.

Отдельные сценарии:

```sh
# один файл
TEST_TARGET_HOST=127.0.0.1 uv run pytest test_vlan.py

# один тест
TEST_TARGET_HOST=127.0.0.1 uv run pytest test_vlan.py::TestVLAN::test_vlan

# с видимым браузером, чтобы посмотреть, что происходит
TEST_TARGET_HOST=127.0.0.1 uv run pytest test_vlan.py --headed

# замедленный прогон для отладки
TEST_TARGET_HOST=127.0.0.1 uv run pytest test_vlan.py --headed --slowmo 500

# самые медленные тесты
TEST_TARGET_HOST=127.0.0.1 uv run pytest . -n 4 --durations=10
```

Тесты работают под учётной записью `selenium`, которая заводится при первом
старте приложения. Каждый тест создаёт свою сеть и удаляет её за собой, но при
прерванном прогоне сети остаются. Накопившийся мусор замедляет `/home`, потому
что страница рисует превью для каждой сети: на 259 сетях её загрузка занимала
30 секунд против 0.1 секунды на пустом списке. Удалить остатки:

```sh
docker exec miminet-postgres psql -U postgres -d miminet -c \
  "SELECT count(*) FROM network n JOIN \"user\" u ON u.id=n.author_id WHERE u.email='selenium';"
```

Сети этой учётной записи можно удалять целиком — они все создаются тестами.
Сети остальных пользователей не трогать.
